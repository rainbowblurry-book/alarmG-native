# ClockGuard: Architecture

> Describes `main` after the native-engine merge (2026-11-01). Verified in code, `tsc`, `expo prebuild`, CI builds, and a device test reported by the user (see STATUS.md).
> For the previous design (config-plugin engine, sound inside the screen), see git history at `bb4bff1` / `c0aa39d`.

## 1. What the app is
An Android-only alarm clock. When it rings you can't simply dismiss it:
1. **Movement:** the accelerometer must count N movements (default 15, 10–500, optional).
2. **Barcode:** you scan the household item you registered in Setup.
3. **Snooze** is only possible with your own 10-digit PIN. Snooze length 1–20 min (default 5). Optional cruelty mode halves each further snooze (floor 20 s).

There is one alarm with repeat days (Sun=0 … Sat=6).

## 4. Engine state machine (native, persisted)
`idle` → (scheduled ring / snooze end / test ring fires) → `ringing` → PIN snooze → `snoozed` → (snooze end) → `ringing` → mission → `disarm()` → `idle`.

| Who | What |
|---|---|
| `arm(h, m, days)` | Checks notifications, exact alarms and full-screen access, otherwise throws a coded error and arms nothing. Saves the schedule and calls `setAlarmClock` for the next matching day. |
| Ring time limit | When ringing starts, the service schedules an exact `RING_TIMEOUT` alarm for session start + 90 min (at least 5 min from now). Snooze, disarm and test exit cancel it. If it fires while still ringing, `RingSession.giveUp`: idle, volume restored, "Missed alarm" notification, still armed (D-36) |
| `cancel()` | Schedule off. Never stops an active ring or snooze. |
| `AlarmReceiver` RING | `startNewRing`, starts `AlarmRingService`, and schedules the next repeat day in `finally`. If the service can't start, it posts a backup notification whose own sound loops (FLAG_INSISTENT). |
| `AlarmRingService` | Foreground service (`systemExempted`, else `mediaPlayback`). Plays a looping MediaPlayer with USAGE_ALARM, vibrates, holds a partial wake lock, and posts an ongoing CATEGORY_ALARM notification with a full-screen intent. `stopWithTask=false` and START_STICKY. |
| `snooze(sec)` | Only while ringing. Schedules the snooze-end exact alarm **first**; if that fails the alarm keeps ringing. Then stops the service, restores the volume and shows a "snoozed until" notification. |
| `disarm()` | Ring or snooze → idle, service stopped, volume restored. **The schedule stays armed** and the next day is rescheduled. |
| `BootReceiver` | On reboot, update, time or timezone change, or the exact-alarm permission being granted: reschedules. Resumes an interrupted ring through a 3-second exact alarm (a foreground service can't be started directly from boot). |
| `RingingActivityListener` | `setShowWhenLocked`, `setTurnScreenOn` and keep-screen-on **only while ringing**. |

### Power / Back / Home (D-20)
- Sound and state live in the service, so turning the screen off, Back, Home and Recents never silence, snooze or disarm.
- Back is consumed by the ringing screen (JS `BackHandler`).
- After a screen-off, the service re-posts a full-screen notification at most **3 times per ring, at least 30 s apart** (best effort, no loop).

### Optional volume boost (D-30, default OFF)
- At ring start, if the ALARM stream is below 60% of max, it is raised once and `(restoreTo, setTo)` is persisted.
- On snooze, disarm or test exit it is restored, but only if the volume still equals `setTo` (the user's own change wins).
- Media, ringtone and notification volumes are never touched.

### Test alarm (TESTING-ONLY, fenced with markers)
- `scheduleTestRing(10)` rings through the same engine.
- `isTestRing` shows a banner and an **Exit test** button (`stopTestRing()`), which only works on test rings and never touches the saved schedule.
- A real ring arriving during a test takes over and clears the test flag.
- Remove later by deleting everything between `TESTING-ONLY START`/`END` markers (Kotlin, `index.ts`, `WakeFlowContext`, `RingingScreen`, `SettingsScreen`).

## 5. Platform limits (honest)
- **Force stop** (Settings → Apps → ClockGuard → Force stop) cancels all alarms and stops the service until the app is opened again. This is an Android rule; no app can avoid it.
- **Removing the app from Recents** is NOT force stop: the scheduled alarm and a ringing service survive (`stopWithTask=false`).
- START_STICKY asks Android to restart a killed service; it is not a guarantee. Samsung battery optimisation can delay or kill apps, so set Battery to Unrestricted.
- The full-screen launch only takes over the screen when the phone is locked or the screen is off. While you are using the phone, Android shows a heads-up notification instead (same as Google Clock).
- Home can't be blocked. The sound continues and the notification brings you back.

## 6. Build pipeline
- `.github/workflows/android-apk.yml` is `workflow_dispatch` only (the file also lives on `main`, because GitHub requires that for manual runs).
- It runs on `ubuntu-latest` with `contents: read` permission, concurrency cancel and a 45-minute timeout.
- Steps: `npm ci`, `tsc`, `expo prebuild`, `gradlew assembleRelease`.
- **With** the 4 `ANDROID_*` secrets: an APK signed with the private key, uploaded as an artifact kept 3 days, and the certificate SHA-256 printed. **Without** them: a compile check only, with no artifact.
